# Практическая работа № 5: Проектирование и реализация REST API с помощью NodeJS (CRUD APP)

Данный проект представляет собой полноценное веб-приложение для управления списком телефонных контактов (телефонная книга) с поддержкой всех базовых операций **CRUD** (Create, Read, Update, Delete) в соответствии с методическими указаниями к **Практической работе № 5**.

---

## 1. Архитектура и стек технологий

- **Серверная часть:** Node.js (v18+ / v22), Express, Body-Parser, CORS, MongoDB Driver.
- **База данных:**
  - Поддержка подключения к **MongoDB** по URI из переменной окружения `MONGODB_URI` (например, MongoDB Atlas или локальный `mongodb://localhost:27017/test`).
  - При отсутствии запущенного демона MongoDB активируется встроенное файловое хранилище [`data/contacts.json`](file:///home/xaneodev/api/part5/data/contacts.json), эмулирующее операции коллекции MongoDB (с генерацией 24-значных hex `ObjectId`), благодаря чему приложение работает автономно без дополнительных настроек СУБД.
- **Клиентская часть (Frontend):** Адаптивное SPA-приложение на базе Bootstrap 5, реализующее двухколоночный интерфейс (список контактов слева и форма редактирования/создания справа) по аналогии с Angular-компонентами из методички (листинги 5.5–5.7).
- **Развёртывание:** Включён файл конфигурации [`Procfile`](file:///home/xaneodev/api/part5/Procfile) (`web: node server.js`) для деплоя на Heroku, Render, Railway или любой другой PaaS-хостинг.

## 2. Маршруты REST API (Таблица 5.1 методички)

Базовый URL: `http://localhost:8080` (или порт из `process.env.PORT`)

| Метод | Конечная точка (Endpoint) | Альтернативный алиас | Описание действия |
|---|---|---|---|
| **GET** | `/v1/contact` | `/api/contacts` | Получить список всех контактов из базы |
| **POST** | `/v1/contact` | `/api/contacts` | Добавить новый контакт в базу данных |
| **DELETE** | `/v1/contact` | `/api/contacts` | Удалить все контакты из базы данных |
| **GET** | `/v1/contact/:id` | `/api/contacts/:id` | Получить данные конкретного контакта по ID |
| **PUT** | `/v1/contact/:id` | `/api/contacts/:id` | Обновить данные контакта по ID |
| **DELETE** | `/v1/contact/:id` | `/api/contacts/:id` | Удалить контакт по его ID |

## 3. Запуск приложения

### 3.1. Установка зависимостей и запуск
```bash
npm install
npm start
```
Сервер будет запущен на порту **8080** (или на порту, указанном в переменной `PORT`):
- **Веб-интерфейс:** `http://localhost:8080/`
- **Конечные точки API:** `http://localhost:8080/v1/contact`

### 3.2. Развёртывание на Vercel

Проект настроен для запуска Express-приложения как Vercel Function. Для сохранения данных в облаке нужна MongoDB, так как файловое хранилище Vercel не предназначено для постоянного хранения.

1. Создайте бесплатную базу MongoDB Atlas и разрешите сетевой доступ к ней для Vercel (`0.0.0.0/0` в Network Access).
2. Импортируйте этот репозиторий в Vercel и оставьте настройки сборки по умолчанию.
3. В **Project Settings → Environment Variables** добавьте `MONGODB_URI` со строкой подключения Atlas. Включите переменную для Production (и Preview, если нужно).
4. Запустите Deploy или сделайте новый deploy после добавления переменной.

Конфигурация в `vercel.json` направляет запросы сайта и API в Express-приложение. API остаётся доступен по адресам `/v1/contact` и `/api/contacts`.

**Запрос:**
```bash
curl -i -X GET http://localhost:8080/v1/contact
```

- **HTTP Статус:** `200 OK`
- **Ответ (JSON):**
```json
[
  {

    "name": "Иван Иванов",
```

### 4.2. Получение контакта по идентификатору ID (GET)

**Запрос:**
```bash
curl -i -X GET http://localhost:8080/v1/contact/67010f3c8a92b95b1f4e1001
```

- **Объяснение:** Метод `GET` с указанием идентификатора ресурса в строке пути (`:id`). Сервер находит соответствующий документ в базе данных и возвращает его.
- **HTTP Статус:** `200 OK`
- **Ответ (JSON):**
```json
{
  "_id": "67010f3c8a92b95b1f4e1001",
  "name": "Иван Иванов",
  "email": "ivanov@mirea.ru",
  "phone": {
    "mobile": "+7 (999) 111-22-33",
    "work": "+7 (495) 123-45-67"
  }
}
```

---

### 4.3. Добавление нового контакта (POST)

**Запрос:**
```bash
curl -i -X POST http://localhost:8080/v1/contact \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Алексей Смирнов",
    "email": "smirnov@mirea.ru",
    "phone": {
      "mobile": "+7 (999) 777-11-22",
      "work": "+7 (495) 888-33-44"
    }
  }'
```

- **Объяснение:** Метод `POST` передаёт JSON-структуру с полями нового контакта. Сервер валидирует обязательное поле `name`, генерирует уникальный `_id` (ObjectId) и сохраняет запись в базу.
- **HTTP Статус:** `201 Created`
- **Ответ (JSON):**
```json
{
  "name": "Алексей Смирнов",
  "email": "smirnov@mirea.ru",
  "phone": {
    "mobile": "+7 (999) 777-11-22",
    "work": "+7 (495) 888-33-44"
  },
  "_id": "3c9d1213796c77d9849e82f6"
}
```

---

### 4.4. Полное обновление данных контакта (PUT)

**Запрос:**
```bash
curl -i -X PUT http://localhost:8080/v1/contact/3c9d1213796c77d9849e82f6 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Алексей Смирнов (Руководитель IT)",
    "email": "smirnov.lead@mirea.ru",
    "phone": {
      "mobile": "+7 (999) 777-99-00",
      "work": "+7 (495) 888-00-00"
    }
  }'
```

- **Объяснение:** Метод `PUT` находит запись с заданным ID и обновляет все переданные атрибуты (имя, почту, телефоны).
- **HTTP Статус:** `200 OK`
- **Ответ (JSON):**
```json
{
  "name": "Алексей Смирнов (Руководитель IT)",
  "email": "smirnov.lead@mirea.ru",
  "phone": {
    "mobile": "+7 (999) 777-99-00",
    "work": "+7 (495) 888-00-00"
  },
  "_id": "3c9d1213796c77d9849e82f6"
}
```

### 4.5. Удаление контакта по идентификатору (DELETE)

**Запрос:**
```bash
curl -i -X DELETE http://localhost:8080/v1/contact/3c9d1213796c77d9849e82f6
```

- **Объяснение:** Метод `DELETE` удаляет указанный контакт из базы данных.
- **HTTP Статус:** `200 OK`
- **Ответ (JSON):**
```json
{
  "_id": "3c9d1213796c77d9849e82f6",
  "message": "Контакт успешно удален."
}
```

---

### 4.6. Проверка результата удаления (GET)

**Запрос:**
```bash
curl -i -X GET http://localhost:8080/v1/contact/3c9d1213796c77d9849e82f6
```

- **Объяснение:** Запрос к удаленному ресурсу возвращает статус `404 Not Found` с сообщением об ошибке.
- **HTTP Статус:** `404 Not Found`
- **Ответ (JSON):**
```json
{
  "error": "Контакт с указанным ID не найден."
}
```

---

### 4.7. Удаление всех контактов (DELETE)

**Запрос:**
```bash
curl -i -X DELETE http://localhost:8080/v1/contact
```

- **Объяснение:** Метод `DELETE` без указания ID очищает коллекцию контактов.
- **HTTP Статус:** `200 OK`
- **Ответ (JSON):**
```json
{
  "message": "Все контакты успешно удалены.",
  "count": 2
}
```
